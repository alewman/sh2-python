# Provenance

Audit of 2026-11-13 (provenance audit wave 1), against the family charter's
"Licences and provenance" rules: nothing copied or transcribed from GPL, LGPL
or unlicensed code; facts about the chip are not code; other emulators may be
run as closed boxes; permissive sources are used with their notice kept.

No GPL source was opened for this audit. Evidence is this repository's own
records: docstrings, `docs/undocumented-behavior.md`, `docs/validation.md`,
`scripts/pinned_repos.json` and `pinned_files.json` (whose notes show that the
Phase 0 research read the GPL references it fetched: Mednafen, Ymir, Kronos,
Yabause, jgenesis, and the unlicensed srg320 RTL). `provenance_check.py` was
run against the permissive references only (below).

## Wave 2 rewrite (2026-11-19)

Mode: **in place**. The flagged pieces were localised (one module, one read
rule, one value, some documents); the rest of the core was clean in wave 1.

Removed unread: `src/sh2_python/divu.py` was moved to a git-ignored `trash/`
whole (its register map, access path and state methods, which wave 1 marked
clean, were read and kept; the division bodies, `partial_64` and the module
docstring's description of them were not), and the three DIVU tests that
encoded the flagged behaviour were moved out of `tests/test_modules.py` by line
range without display. Two flagged lines were seen while locating the code
(`grep` output of the comments, and the three-line non-overflow tail of
`_divide_64`); nothing of them was reused beyond what HM states.

Closed-box route tried: jgenesis `d41e2d9` through the jgenesis harness
(a probe of 35 edge cases). It saturates on overflow but models no early state,
and panics on H'80000000 ÷ −1, so it cannot measure the partial results.
Mednafen would need a Saturn BIOS and a Saturn program from an SH toolchain
(none here); srg320's RTL would need its port list read and a Verilog
simulator (none installed). So the early state is HYPOTHESIS.

Edge cases, old (wave 1 build, run as a closed box) → new:

| Case | Old | New | New source |
| --- | --- | --- | --- |
| 32 ÷ 32, H'80000000 ÷ −1 | no overflow, quotient H'80000000, remainder 0, 39 states | overflow (OVF), DVDNTL = DVDNT = H'7FFFFFFF with OVFIE = 0, 6 states | DOC HM 10.3.3 (+2^31 is out of range) |
| 64 ÷ 32, quotient exactly H'80000000, divisor > 0 (e.g. −2^31 ÷ 1) | overflow | no overflow, quotient H'80000000 | DOC HM 10.3.3 (in range) |
| 64 ÷ 32, quotient exactly H'80000000, divisor < 0 | no overflow | no overflow (same) | DOC |
| both negative, quotient H'7FFFFFFF, remainder ≠ 0 (−H'FFFFFFFF ÷ −2) | no overflow | overflow, DVDNTL = H'7FFFFFFF | DOC HM 10.3.3, read literally |
| ÷ 0, OVFIE = 0: DVDNTL | H'7FFFFFFF / H'80000000 by dividend sign | same | HYPOTHESIS (sign); jgenesis OBSERVED agrees |
| ÷ 0 and every overflow: DVDNTH (and DVDNTL with OVFIE = 1) | the earlier build's partial (e.g. 32 ÷ 0 of 5: DVDNTL H'2F with OVFIE) | PM example-4 state after 3 steps (5 ÷ 0: H'2B; 2^60 ÷ 2: DVDNTH H'7FFFFFF2 against the old H'7FFFFFE4) | HYPOTHESIS (`early_state`) |

## History rewrite (2026-11-22, wave G)

The family's history clean-up (wave G) removed `validation/jgenesis_harness/` (our Rust
harness, built linked with jgenesis' GPL-3.0 `sh2-emu`) and
`scripts/build_jgenesis_harness.py` (which assembles that build and patches a copy of
`sh2-emu`'s source with a `registers_mut()` accessor) from every commit with `git
filter-repo`, keeping the single commit of the 2026-11-21 reset. By the family's rule of
2026-11-19 both are GPL tools. They are kept with the family's other GPL tools
(emu-tools-gpl, `tools/sh2-python`): with `EMU_TOOLS_GPL` naming a checkout of
emu-tools-gpl, run `python "$EMU_TOOLS_GPL/tools/sh2-python/build_jgenesis_harness.py"`
from this checkout (until 2026-11-24 the folder was named by `SH2_GPL_TOOLS`) and the binary lands where it did,
`reference/build/jgenesis-sh2/target/release/sh2-jgenesis-harness`. Commit hashes cited
from before that date refer to the old history, which is kept privately.
