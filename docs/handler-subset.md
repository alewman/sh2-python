# The handler subset

The instruction handlers keep to a small, declared part of Python, so that a cached
interpreter or a code generator can read each one as data: what it reads, what it
writes, which bus accesses it makes and in what order. This file names that subset.
`tests/test_handler_subset.py` checks it on the syntax tree, the way rung 0 checks the
docstrings (`tests/test_readability.py`). Decision J2 of
emulator-lineage/docs/proposals/2026-11-decisions.md asked for both, and
2026-11-jit.md says what they are for. Written 2026-11-25 from `_decode.py` and the seven
handler mixins as they stand. Nothing here changes behaviour (the gate is at the end).

The subset describes what the handlers already did, with one exception, which was
brought inside by a move that changes nothing: TAS.B (below, "The one handler that was
outside").

## What a handler is

- **One per decode row.** `_decode.py` (generated by `scripts/gen_decode.py` from PM
  table A.50 and table 7.2) gives every form its mask and match, its handler's name, its
  pipeline class, its states and its PM section: 142 forms, 142 handlers. Encodings no
  row matches go to `_illegal` (`_core.py`). The step (`_core.py` `step()`) calls
  `self._table[op](self, op)`. Nothing else in `step()` depends on which handler ran,
  except the per-opcode tables built beside it (`cpu.py`: plan, load-use registers,
  slot-illegal, interrupt-blocking).
- **Signature `(self, op)`, no return value.** `op` is the 16-bit opcode. The handler
  pulls its own fields out with shifts and masks: `(op >> 8) & 15` is the `n` field
  (bits 11-8; also the register of `JMP @Rm`, `BRAF Rm`, `LDC Rm,SR`, which PM codes as
  `mmmm` in bits 11-8), `(op >> 4) & 15` is `m`, `op & 0xFF` an 8-bit immediate or
  displacement, `op & 15` a 4-bit displacement, `op & 0xFFF` a 12-bit one.
- **Where they live.** `_transfer.py`, `_arith.py`, `_multiply.py`, `_logic.py`,
  `_shift.py`, `_branch.py`, `_system.py`, one family each (rung 0 checks who owns
  which mnemonic).

## The state a handler may touch

| State | Read | Written | By |
| --- | --- | --- | --- |
| `R[0..15]` | yes | by subscript only (`R[n] = ...`), never rebound | most handlers |
| `sr` | yes | yes | flags (T, Q, M) by many; the whole of SR (I3-I0 included) only by `LDC Rm,SR`, `LDC.L @Rm+,SR`, `RTE` |
| `gbr`, `vbr`, `mach`, `macl`, `pr` | yes | yes | the transfers, LDC/LDS, the multiplier, `BSR`/`BSRF`/`JSR` |
| `pc` | yes: the handler's address + 2 (`_core.py`); PC-relative forms use `self.pc + 2` | only by `BT` and `BF` (taken: the jump is at once) | |
| `delay_target` | no | the delayed branches (`BRA`, `BSR`, `BRAF`, `BSRF`, `JMP`, `JSR`, `RTS`, taken `BT/S` and `BF/S`) and `RTE` | |
| `sleeping` | no | `SLEEP` only | |

`R` may be bound to a local (`R = self.R`) and indexed through it. Nothing else of
the chip is visible: no module (`self.cache`, `self.frt`, ...), no pipeline state
(`_p_*`), no host hook (`observe`, `read`, `write`, `on_*`), no clock, no flag of the
stepper (`_address_error`, `_no_interrupt`). Those belong to the bus methods and to
`step()`.

**Values.** Registers hold integers in 0..2^32-1. A handler masks what it stores
(`& M32`, or a narrower mask) or stores something already in range (a register, an
`& 0xFF`). Python's integers are unbounded, so the widths of intermediates are part of
the semantics a generator has to keep: a carry sum is 33 bits (`ADDC`, compared with
`M32`), a signed sum or difference about 34 bits (`ADDV`, `SUBV`, range-checked), a
product 64 bits (`DMULS.L`, `DMULU.L`, `MAC`), and `MAC`'s 64-bit accumulate wraps to 64
bits in `_set_mac`. Signed views come from the helpers (`_s32`, `_s16`); negative
Python integers appear only inside an expression and are masked before being stored.

**Order is semantic.** The order of statements, and so of bus calls and register
writes, is the manual's: `MAC.W @Rm+,@Rn+` reads `@Rn`, increments Rn, then reads
`@Rm` (so `n == m` reads two consecutive words); `MOV.L @Rm+,Rm` keeps the loaded
value; `BSRF` reads Rm before writing PR. A generator keeps statement order.

## Bus access: only the named bus methods

A handler reaches memory only through these `_core.py` methods, each one data access,
which is one MA of its pipeline class:

| Method | Access | MAs |
| --- | --- | --- |
| `_read8`, `_read16`, `_read32` | a read, zero-extended | 1 |
| `_write8`, `_write16`, `_write32` | a write; the value is masked to the width here | 1 |
| `_tas8` | TAS.B's cache-through read and its write with bit 7 set; returns the byte read | 2 |

Each one routes by A31-A29 (HM table 8.2) to the cache, the external bus, the arrays,
the purge space or the on-chip modules. A misaligned access sets the address-error flag
and is not made (a read gives 0). The handler does not branch on it and runs to its end,
because the exception comes after the instruction completes (HM 4.3.2). A generator
must not add an early exit there.

`_enter(vector, saved_pc, level)` is the one control primitive: exception entry (push
SR, push PC, read the vector, jump; HM 4.3.2-4.5; three MAs). Only `TRAPA` and
`_illegal` call it. Its effects (R15, SR's mask, `pc`, `delay_target`, the stepper's
flags) are its own, documented on it, and are not part of the handler's footprint.

## Constructs

Allowed, and all the handlers use:

- assignment, augmented assignment, tuple unpacking (`n, m = ...`), `if`/`elif`/`else`,
  the conditional expression, `return` (helpers only);
- integer constants, and the module's integer constants (`M32`, `T`, `Q`, `M`, `S`,
  `SR_MASK`, `VECTOR_ILLEGAL`);
- `+ - *`, `& | ^ ~ << >>`, unary `-`, comparisons including chained ones,
  `not and or`, and `in` against a tuple of constants;
- calls of three kinds only: the bus methods and `_enter` above; the shared methods
  `_set_t` (T from a condition), `_set_mac` (a 64-bit value to MACH:MACL), `_push` and
  `_pop` (STC.L/STS.L and LDS.L's stack forms), which are linted as handlers are; and
  the pure module-level helpers `_s32`, `_s16`, `_sext8`, `_sext16`, `_disp8`,
  `_disp12` and `div1_step` (shared with the DIVU's model, `divu.py`), which see no
  `self` and call nothing but each other, `int` and `bool`.

Not allowed (none is used): loops, comprehensions, lambdas, nested functions, `try`,
`with`, `raise`, `global`, `nonlocal`, imports, `/`, `//`, `%`, `**`, floats, strings
other than the docstring, lists, dicts, sets, `None`, `is`, attribute chains
(`self.cache.enabled`), `getattr` and any other builtin, any call of a host hook.
So there is **no dynamic dispatch** (no handler picks another handler or method by
value), **no I/O** (no printing, logging or files; the bus methods' callbacks are the
only way out, and only through those methods), and **no hidden state** (no globals
written, no class or closure state, no default-argument state, nothing kept between
calls but the named state above).

## Timing

Handlers hold no timing. A handler's cost is data, from three places:

1. **Its pipeline class**, the decode row's `pipeline` field, which names PM table 7.2's
   row in `pipeline.py` (`CLASSES`, compiled to `PLANS`): the stages after ID, which
   slots are MAs, the next instruction's ID stall, the multiplier's `mm` states, and
   how the class redirects fetches (plain, conditional branch, delayed branch, trap,
   sleep).
2. **Per-opcode tables** built in `cpu.py` from the decode table: the register a load
   writes in WB and the registers the load-use rule sees used (PM 7.5).
3. **The bus.** Each bus-method call opens the class's next MA (`pipeline.py`
   `_ma_next`), so a handler's *k*-th data access is its class's *k*-th MA, and that MA
   lasts what the BSC and the board make the access (port width, waits, SDRAM, the write
   buffer, cache hit or fill). MAs the handler did not use (a multiplier's MA, an access
   that faulted) are closed by `_retire`.

The lint checks the one link between the two: along any path through a handler, its
data accesses (helpers and `_enter` included) are no more than its class's MAs. For
example, `AND.B` 2 of 2, `MAC.L` 2 of 2, `TRAPA` 3 of 3, `MUL.L` 0 of 2.

## Sync points: where a handler may reach another domain

Only a bus-method call can leave the CPU. 89 of the 143 handlers make none: those are
pure register transforms, and a block of them cannot be observed from outside before
its end. For the other 54, whether a given access reaches another domain depends on its
address at run time (HM table 8.2):

| A31-A29 | Space | Reaches |
| --- | --- | --- |
| 000, cache on, hit (reads) | cache | nothing outside the chip; the other SH-2 cannot see it, and the cache is not coherent with it (that is the cache-through alias's job) |
| 000 miss or write; 000 with the cache off; 001 | external bus | the board: a callback at `chip.clock`, which may add waits and change pins (`irl`, `nmi`, `dreq*`) from inside it. **Sync point.** Writes go through the write buffer and are still made in order |
| 010 | associative purge | the cache: **invalidates lines** (a compiled-block invalidation event) |
| 011, 110 | address array, data array | the cache's arrays; a data-array write can change code run from there (fetches in space 110 read it) |
| 111, H'FFFFFE00- | on-chip modules | the chip's own modules. A write may change interrupt levels and vectors (INTC), start a DMA, stall the CPU (DIVU), change the cache (CCR), and through the FRT, SCI, DMAC and WDT outputs (`on_ftoa`, `on_txd`, `on_dack`, `on_wdtovf`) reach the board. **Sync point** |
| 100, 101 | reserved | nothing (U10) |

`_tas8`'s read and write are one locked pair: the bus is not released between them
(HM 7.10), so the pair is one sync point, never split by another master's cycle. That is
why it is one method.

Beyond the accesses themselves, a block of cached handlers must also respect what
`step()` decides between instructions, which the handlers leave to it:

- **Interrupt acceptance** at every instruction boundary (HM 4.4, 5.4), except after a
  delayed branch (its slot follows) and after LDC, LDC.L, STC, STC.L, LDS, LDS.L, STS and
  STS.L (HM 4.6.2; `cpu.py` `INTERRUPT_DISABLING`). The mask changes only in
  `LDC Rm,SR`, `LDC.L @Rm+,SR`, `RTE` and exception entry. Not linted: the other `sr`
  writers change only T, Q, M or S, which holds by reading them, not by a check.
- **Control flow ends a block**: the handlers that write `pc` (`BT`, `BF`) or
  `delay_target` (the delayed branches and `RTE`, after their slot), `SLEEP`
  (`sleeping`), and `TRAPA`/`_illegal` (`_enter`). The lint checks that no other handler
  has these effects.
- **Address errors** set by a bus method are taken at the next boundary outside a slot.

## The one handler that was outside

`TAS.B @Rn` (`_logic.py`) did its own bus work: it opened its MAs itself (`_p_ma_left`,
`_ma_next`), called the host hook `observe`, went below the bus methods (`_bus_read`,
`_bus_write`), looked into the cache (`self.cache.enabled`, `self.cache.write_hit`),
compared with `None`, and set the stepper's `_address_error`. It is the one instruction
whose access is neither a cached read nor a plain write (HM 8.4.4: a cache-through read,
then a write that updates a hit line) and whose two cycles are locked together (HM 7.10).

The fix moves that body, unchanged line for line, into the new bus method `_tas8` in
`_core.py`, beside `_read8`/`_write8`. The handler now reads
`value = self._tas8(self.R[n])` and sets T. No named exception remains. The lint, run
against `main` (8824075), reports that handler's 23 violations and nothing else.

## Checks

`tests/test_handler_subset.py`, 450 tests:

- each handler, with every helper it reaches, keeps to the subset (143);
- each handler's control effects belong to its class (143);
- each handler's data accesses fit its class's MAs (143);
- every shared helper is used, and no `_op_` method is missed (1);
- the lint passes a clean handler and catches each of 19 seeded faults: a loop, I/O, a
  `getattr` dispatch, a dispatch through a table, a division, a write to the clock, a
  reach into a module, a host hook, a call below the bus methods, a call into the
  scheduler, a rebinding of `R`, a read of write-only state, an unknown name, a builtin
  off the list, a float, a list, a lambda, a handler's return value, a `global` (20).

`python tests/test_handler_subset.py` prints each handler's footprint (state read,
state written, bus methods, MAs), one line each, for a generator or a reader.

**Gate for the TAS move** (2026-11-25): the fast suite (`pytest`, rungs 0-4 fast)
619 passed, 1 skipped before; 1,069 passed, 1 skipped after (619 + 450), on CPython 3.14
and PyPy 7.3.23. ruff check and format are clean. A byte-identity probe recorded every
bus callback (address, width, value, kind, start state), every `observe` event and every
step's states and registers. It covered TAS.B in the cache area, the cache-through area,
an odd byte, the purge space and on-chip space (address errors), with the cache off, on,
and on in two-way mode, in a delay slot, and on all 114 rung-1 corpus cases containing
TAS.B. Its output was identical before and after (SHA-256 9c4684254f67...). The skip is
rung 4's ROM-bytes check of 32xspd, whose ROM is not fetched into the worktree.
